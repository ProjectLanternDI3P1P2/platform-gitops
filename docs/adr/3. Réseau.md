Nous avons choisi d'utiliser le pare-feu pfSense pour filtrer le traffic réseau.
La raison principale d'avoir ça au lieu d'avoir seulement Kubernetes, c'est de pouvoir filtrer le réseau également au niveau des autres logiciels que l'on héberge (supervision, sauvegarde, logs, métriques).

Les modules fournis par les devs ne seront pas dans le même espace Kubernetes que nos autres services, qui seront dans des espaces par thèmes.

Les différentes machines du cluster Proxmox sont reliées par un VXLAN, une fonctionnalité native de Proxmox dans SDN.
On a essayé de d'utiliser d'autres solutions, mais toutes ajoutent de la complexité dans la configuration, ou demandent une interface réseau supplémentaire.
Le flux entre les nœuds du cluster ne sont pas chiffrés, en revanche le contenu du flux des nœuds et masters Kubernetes sont chiffrés, ainsi la donnée applicative n'est pas lisible avec une attaque man-in-the-middle.
Ce choix nous permet également de n'avoir qu'un seul pfSense nécessaire pour accéder à tous les nœuds Kube, il est donc en actif-passif.
