# Keycloak

Keycloak belongs to the `keycloak` namespace. Its dedicated PostgreSQL
database is hosted by the production CloudNativePG cluster in the `database`
namespace. It does not share the application database named `lantern`.

- Public OIDC base address: `https://groupe7.diiage.org/auth`.
- Keycloak image: `10.4.111.200:18443/lantern/keycloak-theme:v0.3.0`, running
  with `start`.
- Database: `keycloak`, owned by the `keycloak` role.
- Database Service: `postgres-rw.database.svc.cluster.local:5432`.
- Storage: three CloudNativePG instances, 10 GiB each, on the `longhorn-db`
  StorageClass. PostgreSQL replication provides the three database copies;
  each Longhorn volume therefore uses one replica.
- Service exposure: ClusterIP behind Traefik on host `groupe7.diiage.org` and
  path `/auth`.
- Credentials: existing `keycloak-secrets` Secret, provisioned outside Git.

The reset completed on 2026-10-19 created an empty identity database. Users,
realms and OIDC clients must be configured again. The administration credentials
are reused without being committed to this repository.

`platform/keycloak` records the Keycloak resources for review and subsequent
GitOps adoption. The Application is synchronized automatically without pruning
and is included
by the parent `platform` Application. The database, role and storage are managed
by `apps/database`, whose Application is generated by the K3s ApplicationSet.

The Kubernetes backend remains HTTP behind Traefik. The externally visible
OIDC URL is HTTPS and must preserve the `/auth` prefix. Application login and
SSO require configured realms and clients; successful server readiness alone
does not validate those flows.

Before the migration, Keycloak had two desired replicas and its historical
PostgreSQL Deployment had one.
The desired master-realm issuer is
`https://groupe7.diiage.org/auth/realms/master`; validate its discovery document
and an interactive login before enabling dependent SSO. No application SSO test
was performed at that time.

## Completed migration to CloudNativePG and Longhorn

On 2026-11-25, a one-off Job transferred the identity database. The restore
verified matching counts of 2 realms, 17 clients and 8 users. After the switch,
both Keycloak replicas became ready and OIDC discovery responded for the
`master` and `lantern` realms.

The CloudNativePG role uses `database/postgres-role-keycloak`, provisioned
outside Git. The `Database` and `DatabaseRole` use the `retain` policy.

Keep `keycloak/postgresql-keycloak-pvc` during the rollback period. Returning
to the old database requires reconciling writes made on the new database.

Production tracks `main`. Keycloak's automated synchronization keeps the
historical PostgreSQL resources available until the rollback period ends.
